## 🔎 【事象】英数字キーワード（"n8n Youtube"等）で海外動画が抽出される問題

### 1. 発生原因の因数分解（Root Cause Analysis）

YouTube Data API v3の `search.list` エンドポイントに対するリクエスト構造を極小粒度まで分解します。

1. **入力レイヤー**: ユーザーが「n8n Youtube」を入力。
2. **アナライザ到達**: [core/analyzer.py](cci:7://file:///Users/daisukemiyauchi/Documents/GitHub/YouTube-Research-Tool/core/analyzer.py:0:0-0:0) の [find_giant_killing_videos(query="n8n Youtube")](cci:1://file:///Users/daisukemiyauchi/Documents/GitHub/YouTube-Research-Tool/core/analyzer.py:11:4-119:26) がコールされる。
3. **APIラッパー到達**: [core/youtube_client.py](cci:7://file:///Users/daisukemiyauchi/Documents/GitHub/YouTube-Research-Tool/core/youtube_client.py:0:0-0:0) の [search_videos()](cci:1://file:///Users/daisukemiyauchi/Documents/GitHub/YouTube-Research-Tool/core/youtube_client.py:9:4-48:21) がコールされる。この時、引数 `region_code` と `relevance_language` はデフォルトの `None` である。
4. **APIエンドポイント挙動**: 
   - YouTubeアルゴリズムは、国や言語の指定（`regionCode`, `relevanceLanguage`）がない場合、**「グローバル検索」**を実行する。
   - 「n8n」「Youtube」は世界共通のアルファベット文字列であるため、言語的バイアスが一切かからない。
   - さらに、本ツールは `order='viewCount'`（再生数順）をデフォ設定にしている。
5. **結果の歪み（論理的帰結）**: グローバル全体で再生数が多い巨大な海外動画がAPIの返却上限（Max 50件）を埋め尽くしてしまい、日本の動画がランキング圏外へ弾き出される。

#### 案A：クエリ文字列の強制修飾（String Manipulation）
- **手法**: 内部で強制的に `query = query + " 日本語"` のように文字列を付与する。
- **検証結果**: 致命的欠陥。完全に日本語のみで構成された良質な動画であっても、タイトルや概要欄に「日本語」という単語が含まれていない限り、逆にアルゴリズムから弾かれる（スコアが下がる）ため、False Negative（偽陰性）が激増する。**[棄却]**

#### 案B：API取得後の事後フィルタリング（Post-Fetch Processing）
- **手法**: グローバル検索で50件取得し、Python側で正規表現（`[あ-んア-ン]`等）を用いて日本語が含まれる動画だけを残す。
- **検証結果**: 構造的欠陥。「n8n」のような世界中で検索されるワードの場合、Top50が**全て海外動画**で埋め尽くされる可能性が高い。その結果、Python側でフィルタをかけた後の抽出件数が「0件」となり、いたずらにYouTube APIクオータ（割当数）を消費するだけのゴミ処理と化す。**[棄却]**

#### 案C：YouTube Data API ネイティブパラメータの注入（Native API Constriction）
- **手法**: [search_videos()](cci:1://file:///Users/daisukemiyauchi/Documents/GitHub/YouTube-Research-Tool/core/youtube_client.py:9:4-48:21) の引数として `region_code='JP'` (日本リージョン) と `relevance_language='ja'` (日本語関連) を明示的に渡す。
